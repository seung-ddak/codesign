# TT pipeline code audit remediation (2026-10-22)

Tracked in [GitHub issue #6](https://github.com/seung-ddak/codesign/issues/6). Branch: `experiment/wide16-experts`.

## Operational scope

**Active, supported research-smoke route:** `run_minimal_geometry_gate.sh` → `run_quick_validation.sh smoke` → Mode 2/4 joint E/S/A reward-guided generation → morphology-specific MJX 2-second replay. One user, one GPU, sequential jobs. Retain fixed CP-Design semantics (reward-agnostic dynamics TT training; task reward at inference; no target-motion imitation).

**Legacy / experimental, not evidence of the current pipeline:** `run_foot_anchored_pipeline.sh` (D4/D5, fixed-E shared SPSA, pose-heldout evaluation), historical first-window and other gate runners. Legacy mode 5 is now accepted by training CLI, but the branch must be assessed separately. It does not automatically prove unseen morphology transfer.

## Audit disposition (14 findings)

| # | Change / current contract | Limit |
|---|---|---|
| 1 | `tt_model.rebase/unbase` normalize cos/sin yaw before any coordinate transform; near-zero yaw → identity | Previous predicted positions/rewards remain historical and uncorrected |
| 2 | `task_reward.p_fall` normalizes gravity *direction*, adds magnitude-consistency penalty; tilt cannot become negative | Reward definition changed; compare only newly regenerated results |
| 3 | `check_fast_smoke` requires explicit unmodified state history and exact zero vertical shift for strict raw success; missing → unknown | MJX completed count remains separate |
| 4 | `check_joint_generation` classifies skipped/null/nonfinite as failed and outputs JSON, no `NoneType` comparison | Does not establish good dynamics |
| 5 | `train_tt --modes` permits Mode 5 matching existing conditioning masks | No new Mode5 checkpoint trained |
| 6 | Foot-Anchored evaluator checks **any test pose row** and labels D4 as trained morphology / pose holdout | Does **not** claim unseen morphology generalization |
| 7 | Initial geometry penetration check is distinct from opt-in dynamic support/flight trial | A transient is not a pass until actual MJX survival |
| 8 | Cross-morphology source episode/group_id stays in same train/val group; split metadata includes rounded unique S0 counts | New split only affects newly trained checkpoints |
| 9 | Train progress validation loss iterates **all** val episodes in deterministic batches, records count | Previous progress logs used small subset |
| 10 | Main/Foot-Anchored/action-pair collectors and generator use **foot vs floor** contact pairs | Old NPZ contact bits cannot be changed retroactively; recollection needed if critical |
| 11 | Smoke JSON explicitly distinguishes gradient graph connectivity from actual physical 2s MJX test | Nonzero gradient is not proof of learned E→dynamics |
| 12 | `audit_rollout_geometry.py` compares rollout survival-valid frames to a separate 2mm penetration criterion; no data removed | **Tool committed but not run**; whole-population statistics unavailable |

| 14 | Active/legacy route and expanded CPU preflight are documented; obsolete contact-fixing test updated | **No verified full pytest or MJX rerun** on user's GPU |

**Important:** This is a code correction series, not evidence that the existing 3000-step TT checkpoint or reward guidance already learned realistic physical transitions. Recollecting contact-bit data or retraining may become necessary later, but these operations are NOT part of this remediation.

## Interpretation gates

1. **CPU/full suite failures:** fix source-level incompatibility before any GPU runs; record actual traceback in issue #6.
2. **Raw S0 vs corrected S0:** `strict_raw_TT_to_MJX_verified` is true only if a complete, explicitly uncorrected candidate finished 2s. Any unknown correction history is not strict success.
3. **MJX:** verified actual 2s survival and reward are required. Projection-assisted or transient/airborne starts must be named separately.
4. **Next learning step:** only after reliable physical metrics distinguish dynamics-model mismatch, action feasibility and initial geometry. Do not infer morphology co-design performance from gradient nonzero or TT-predicted reward alone.
