T7 구현 해설

T7 은 형상 생성 모델 TT 의 denoiser ψ 를 DDPO 로 직접 fine-tuning 합니다. 보상은 T5 에서 얼린 보행 정책 πθ 가 그 형상으로 실제로 걸었을 때의 return 입니다. 이 페이지는 코드가 한 update 안에서 무엇을 어떤 순서로 하는지 설명합니다.

기준: 2026-09-30 코드 (A안 vmap 채점 반영)stage2/code/D58

한 update 의 흐름

한 update 는 세 단계입니다. ψ 로 형상 32 개를 만들고, 얼린 πθ 로 채점하고, 그 점수로 ψ 를 한 번 고칩니다. 이 반복을 --updates 번 합니다.

πθ 는 모든 단계에서 얼어 있습니다. 바뀌는 것은 ψ 의 가중치뿐입니다. 다음 update 의 생성은 방금 고친 ψ 로 돌아갑니다.

1 · 생성ddpo_hardware.pygenerate() :148–236

TT 의 원래 추론 루프를 그대로 쓰지 않고, DDIM 한 step 을 직접 풀어 씁니다. DDPO 는 매 step 의 확률이 필요한데, 원래 루프는 그 값을 내주지 않기 때문입니다.

  1. 형상 32 개를 --generation-microbatch 4 개씩 8 번에 나눠 만듭니다. 조건 입력은 단위 행렬 pose 로 채운 더미 궤적이고, hardware_goal/mask 를 전부 켜서 하드웨어 전체를 생성하게 합니다.
  2. 100 step 마다 backbone 으로 노이즈를 예측하고 _ddim_stats 로 다음 상태의 평균 μ 와 표준편차 σ 를 구합니다(eta=1). 거기서 xt−1 = μ + σ·ε 를 뽑습니다.
  3. σ 가 0 인 마지막 t=0 step 은 결정적이라 빼고, 나머지 99 개 transition 마다 상태 xt, xt−1 와 old_log_prob 을 zarr 에 씁니다.
  4. log p 는 활성 차원의 평균입니다(_log_prob). 합으로 두면 차원이 많아 확률비가 쉽게 포화하기 때문입니다.
  5. 디코딩한 링크·관절·액추에이터 값을 bank 에서 가장 가까운 형상으로 바꿉니다(hardware_to_nearest_neighbor_params, local_only=True). 결과는 choices(8 bit)와 seed 이고, 맞는 원형이 없거나 거리가 무한이면 invalid 로 표시합니다.
# ddpo_hardware.py:192–195  한 step 의 확률적 전이
mean, std = self._ddim_stats(sample, pred[name], timesteps)
proposal = mean + std * torch.randn(sample.shape, ..., generator=generator)
next_samples[name] = torch.where(dont_update[name], sample, proposal)

생성 단계는 update 시간의 절반(약 12 분)입니다. step 마다 GPU→CPU 복사와 zarr 청크 (1, 1) 쓰기가 일어나고, bank 매칭은 CPU 한 코어에서 128 개 zarr 를 차례로 비교합니다. 이 부분이 C안 최적화 대상입니다.

2 · 채점design_scorer.pyscore() :97–117

MJX 는 구조가 같은 로봇끼리만 한 번에 계산할 수 있습니다. 그래서 형상을 구조별로 묶고, 묶음마다 컴파일된 rollout 함수를 따로 둡니다.

  1. structure_key(choices) 는 마지막 2 bit 와 bit 5(레일, 제거됨)를 뺀 5 bit 입니다. 이 키가 T5 의 16 개 그룹 중 어디에 속하는지 찾습니다. T5 에 없는 키면 ValueError 입니다(옛 T7_try1 실패 원인).
  2. 그룹을 처음 만나면 _group() 이 MultiDesignEnv 를 만들고 rollout 을 JIT 합니다(lazy). 한 번에 약 1 분, RAM +0.4~1.3 GiB 가 듭니다. 이후 update 에서는 재사용합니다.
  3. _stacked() 가 그룹 템플릿의 슬롯에 새 형상의 mjx_model 과 morphology 벡터를 끼워 넣습니다. 슬롯 수는 --slots(현재 1)이라 형상 하나씩 돕니다.
  4. rollout 은 1000 step(20 s)입니다. πθ 는 관측에 붙은 morphology 벡터(choices + uniform)를 보고 행동합니다. 넘어지기 전까지의 보상만 더합니다(ret += reward * alive).
  5. A안: 고정 명령 7 개를 jax.vmap 으로 한 번에 돌립니다. 명령마다 rng 키는 예전 순차 방식과 같게 fold_in(seed, i) 로 만듭니다.
  6. 형상 점수 = 7 명령 return 의 평균. DR·노이즈·push 는 끄고 명령은 고정합니다(D51·D52).

3 · 갱신ddpo_hardware.pyupdate() :247–313
  1. invalid 형상은 그 배치의 최저 valid 점수를 받습니다(train_hardware_guidance.py:87–88).
  2. advantage 는 배치 32 개로 표준화합니다. 모든 점수가 같으면(표준편차 < 1e-6) 갱신을 건너뛰고 psi_updated=False 를 남깁니다.
  3. 32 형상 × 99 step = 3168 transition 을 섞어 --ddpo-minibatch 32 개씩 읽습니다. 한 epoch 에 99 번 역전파하고, 이를 4 epoch 반복합니다.
  4. 각 transition 에서 현재 ψ 로 노이즈를 다시 예측해 μ, σ 를 구하고, 저장된 xt−1 의 log p 를 새로 계산합니다. 그 형상의 advantage 를 99 step 모두에 똑같이 줍니다.
  5. PPO 와 같은 clipped 목적함수로 loss 를 만들고, gradient norm 을 1 로 자른 뒤 AdamW 한 step 을 밟습니다.
  6. 끝나면 zarr buffer 를 지우고 history.jsonl 에 한 줄을 씁니다. 10 update 마다, 그리고 마지막에 psi_XXXX.pt(모델 + 옵티마이저)를 저장합니다.
