One-shot Morphology RL 구현 해설

TT denoiser를 수정하는 대신, 작은 정책 πφ가 latent noise에서 유효 topology 하나와 13개 continuous parameter를 한 번에 뽑습니다. 그 파라미터로 만든 바로 그 로봇을 동결된 보행 정책 πθ로 채점하고 πφ만 갱신합니다.

기준: 2026-10-01 코드stage2/code/D60학습 미실행 · self-check 통과

한 update의 흐름

한 update는 batch만큼의 완성된 morphology를 한 번에 생성하고, 7개 locomotion command 평균 return을 얻은 뒤, 형상별 action log-probability에 terminal advantage를 적용합니다.

πθ와 observation normalization은 읽기 전용입니다. 학습되는 가중치는 one-shot morphology policy πφ뿐입니다.

단계별 구현

0 · 유효 공간train_oneshot_morphology.pyvalid_choices()
  1. TT의 학습 checkpoint나 RoboToken bank를 읽지 않고 canonical generator의 enumerate_choices(COMPONENTS)를 호출합니다.
  2. 열거 결과 138개 중 T5와 호환되는 8-bit, binary, 13-uniform 조건을 모두 만족하는 128개만 남깁니다.
  3. topology action은 이 목록에 대한 categorical index이므로 정의되지 않은 topology는 처음부터 뽑을 수 없습니다.
  4. continuous action은 Beta distribution에서 나오므로 각 값은 자동으로 (0, 1) 안에 있습니다.
# canonical generator가 정의한 4족 보행 범위
choices = [c for c, n in enumerate_choices(COMPONENTS)
           if len(c) == 8 and set(c) <= {0, 1} and n == 13]
assert len(choices) == 128
1 · one-shot 생성MorphologyPolicysample()
  1. 각 episode의 state는 32차원 latent z ~ N(0,I)입니다. 이 값은 corrupted morphology가 아니라 서로 다른 설계를 유도하는 random code입니다.
  2. 두 층의 128-unit tanh MLP가 topology logit 128개와 Beta의 α·β parameter 26개를 출력합니다.
  3. 마지막 head를 0으로 초기화하므로 update 0의 topology는 균등분포이고, 각 continuous parameter는 Beta(1,1), 즉 uniform distribution입니다.
  4. topology 하나와 uniforms 13개가 policy의 단일 joint action입니다. 99개 transition이나 중간 morphology는 없습니다.
  5. 학습용 log-probability는 categorical과 13차원 Beta의 log-probability 합입니다.
# 한 번의 morphology action
topology = Categorical(logits=logits)
continuous = Independent(Beta(exp(alpha), exp(beta)), 1)
choice_index = topology.sample()
uniforms = continuous.sample()
log_p = topology.log_prob(choice_index) + continuous.log_prob(uniforms)
2 · 직접 형상locomotion_env.pydesign_scorer.py
  1. LocomotionEnv는 기존 재현용 seed 입력과 새 uniforms 직접 입력을 모두 지원합니다. 둘을 동시에 주거나 13개가 아니거나 범위를 벗어나면 즉시 중단합니다.
  2. umi_on_legs_plus_plus_from_params(choices, uniforms)로 MJCF를 만들고 기존과 동일하게 arm/rail subtree를 제거합니다.
  3. morphology observation은 T5 때와 같은 [8 choices, 13 uniforms] 21차원입니다. 따라서 frozen πθ의 입력 계약을 바꾸지 않습니다.
  4. DesignScorer._stacked()는 두 번째 값이 scalar면 과거 seed 방식, vector면 direct uniforms 방식으로 환경을 만듭니다.
  5. structure group별 MJX lazy JIT, 1000-step rollout, 고정 명령 7개 vmap, DR·noise·push off는 T7 DDPO 평가와 동일합니다.

nearest bank로 다른 로봇을 고르는 단계가 없습니다. πφ가 출력한 uniforms로 생성한 실제 geometry가 곧 채점 대상입니다.

3 · horizon-1 갱신train_oneshot_morphology.pymain()
  1. 기본 batch 16개 형상의 return을 평균과 표준편차로 정규화합니다. 모든 return이 같으면 학습 신호가 없으므로 update를 건너뜁니다.
  2. 같은 latent와 sampled action의 현재 log-probability를 다시 계산하고, 기존 ddpo_clipped_loss를 일반적인 PPO clipped objective로 재사용합니다.
  3. topology entropy를 log(128)로, continuous entropy를 13으로 나누어 합하고 entropy_coef=0.01로 collapse를 늦춥니다.
  4. gradient norm은 1로 제한합니다. 기본값은 PPO epoch 1이라 같은 batch를 반복해서 과적합하지 않습니다.
  5. history.jsonl에는 생성한 실제 choices·uniforms·return과 entropy·KL·clip·gradient norm을 남깁니다.
# 하나의 terminal reward가 하나의 morphology action에 대응
A = (returns - returns.mean()) / returns.std()
loss_ppo, diagnostics = clipped_loss(log_p_new, log_p_old, A, 0.2)
loss = loss_ppo - 0.01 * normalized_entropy

검사와 현재 한계

  1. 학습 결과는 아직 없습니다. 문법 검사와 --self-check만 실행했습니다. self-check는 policy sample shape·범위·log-probability와 seed 방식/direct-uniform 방식의 geometry 동일성을 확인합니다.
  2. 목표는 frozen πθ에 특화됩니다. return 개선은 보편적으로 가장 좋은 로봇이 아니라 현재 controller가 가장 잘 제어하는 로봇을 찾았다는 뜻입니다.
  3. arm/rail 제거 후 무효 parameter가 남을 수 있습니다. canonical 13 uniforms 중 실제 보행 geometry를 바꾸지 않는 차원은 학습 후 sensitivity 분석으로 식별해야 합니다.
  4. 형상당 평가 seed는 update당 하나입니다. batch 안에서는 같은 seed를 써 비교 noise를 줄이지만, 최종 성능 판단은 별도 seed 반복 평가가 필요합니다.
  5. 동일 simulation budget의 random baseline이 필요합니다. 첫 smoke 20×16=320개 평가와 uniform random 320개를 비교해야 policy learning 효과와 단순 best-of-N 효과를 분리할 수 있습니다.
