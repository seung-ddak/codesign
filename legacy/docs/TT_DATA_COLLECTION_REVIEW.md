# TT 데이터 수집 계획

**목표는 추종 정확도보다 실제 행동·형상 다양성을 확보하는 것이다.** 처음부터 모든 형상에 100개 동작을 실행하지 않고, 작은 실험에서 데이터 품질과 수집 속도를 확인한 뒤 확대한다.

## 무엇을 모을까

| 데이터 | 방법 | 목적 |
|---|---|---|
| 다양한 동작 | 기본 모션·전환을 조합해 실제 10초 실행 | 상태·행동 범위 확보 |
| 형상 비교 | **같은 관절 목표**를 여러 E에서 실행 | 형상이 결과에 미치는 영향 |
| 행동 비교 | **같은 E·초기 상태**에서 행동만 변경 | 행동이 결과에 미치는 영향 |

- 명령이 달라도 실제 움직임이 비슷하면 중복이다. 속도·회전·정지·접지 패턴으로 선별한다.
- 형상 간 같은 행동의 반복은 비교에 필요하므로 제거하지 않는다.
- 성공·실패 모두 저장한다. 낙상을 일으킨 마지막 정상 수치의 전이도 포함하고, reset 전후를 연결하지 않는다.

## 환경은 어떻게 고정할까

최근 PPO 기준으로 **30Hz 제어·300Hz 물리 계산, KP 30·KD 0.5, 토크 ±33.5N·m, 마찰 0.8, 자기 충돌 끔·바닥 충돌 유지**로 시작한다.

- Topology `00000011`과 무릎 방향을 유지한다. 현재 비활성 E 좌표 **0·11·12는 0.5로 고정**한다.
- 나머지 E를 고르게 샘플링하고, 실제 길이·질량·관성·장착각의 차이도 확인한다.
- 초기 상태는 형상별로 검증한다. e000의 자세를 다른 형상에 그대로 복사하지 않는다.
- **기존 50Hz 데이터와 새 30Hz 데이터를 그대로 섞지 않는다.** TT 학습·생성·평가의 시간 간격도 맞춰야 한다.
- 현재 PPO는 5개 레퍼런스용이다. 새 형상이나 100개 동작에 바로 적용된다고 가정하지 않는다.

## 어떤 순서로 진행할까

| 단계 | 제안 규모 | 확인할 것 |
|---|---:|---|
| 1. 파일럿 | 8형상 × 6공유 동작 × 2seed = **96회** | 정책 적용 범위·실패 패턴·속도 |
| 2. 동작 선별 | 실제 움직임이 다른 **10초 동작 최대 100개** | 다양성·중복률·부족한 동작 유형 |
| 3. 확대 | 32형상 × 공통 20개 + 추가 10개 = **960회** | 형상 효과와 행동 범위 |

100개를 확보하지 못하면 실제 확보 수를 보고한다. train/val/test는 중첩 구간이 아니라 **원본 동작 그룹**으로 분리한다.

## 어떻게 빠르게 모을까

1. 기존 **JAX 수집기·형상 bank**를 재사용하고 정책·모델을 반복 로드하지 않는다.
2. GPU에서 여러 환경과 시간 구간을 묶어 실행한다. 매 프레임 CPU 왕복은 피한다.
3. 배치 **8→16→32→64**를 측정해 채택 전이/초와 GPU·호스트 메모리를 비교한다.
4. 필요한 상태·행동·접촉만 청크 단위로 저장한다. 영상은 대표 표본만 나중에 만든다.
5. 속도를 위해 물리 주기·solver를 먼저 줄이지 않는다.

**저장 원칙:** 실행 행동 T개에 실제 상태 T+1개를 저장한다. 실제 적용한 목표각, E, 물리 설정, 정책 버전, 종료 원인을 함께 남긴다.

**다음 작업은 96회 파일럿과 배치 속도 측정이다.** 위 규모는 시작안이며, 아직 최적 배치·대량 수집 성능을 검증한 것은 아니다.
