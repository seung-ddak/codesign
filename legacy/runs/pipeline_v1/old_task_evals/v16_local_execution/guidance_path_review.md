# v16 후속 점검: 추가 손실 학습 조건과 생성 경로

2026-11-03. 사전 계획 8-49의 분기 B에 해당하는 코드 경로 점검임. 학습이나 추론 알고리즘을 바꾸지 않았음. 물리 평가 완료 전 작성한 점검이며, 최종 수치는 summary.json을 기준으로 함.

## 확인된 사실

- `code/tt_dynamics/train_tt.py`의 `delta_loss`는 Mode1을 사용함. 형상 E, 초기 상태 s0, 전체 행동 A를 알려 주고 미래 상태 S를 예측하는 조건임.
- 최종 변화량 점수도 `eval_v12parity/measure_delta_r2.py`의 Mode1 생성으로 측정함. 실제 미래를 입력하지 않고, 동일 쌍에 같은 초기 잡음을 주어 8회 생성 결과를 평균함.
- 학습 중 단일 잡음 단계의 변화량 점수는 실제 미래에 잡음을 섞은 값을 입력받음. 이 값이 높아도 최종 생성 점수가 높다고 볼 수 없음.
- 실제 공동 생성은 `eval_v12parity/run_eval.py`에서 `generate_task.py --joint-full-guidance --e-rest-s0` 경로를 사용함.
- `joint_diffusion_guidance.py`의 `decode`는 Mode4로 형상을 예측한 뒤, 해당 형상의 초기 상태를 설정하고 Mode2로 행동 A와 미래 상태 S를 함께 생성함. 이후 구간도 Mode2임. 전체 행동을 알려 주는 Mode1 호출은 없음.
- 보상은 이 공동 생성 상태를 기준으로 계산하며, 상태·행동·형상 잡음 모두에 미분값을 전달함. Mode1로 생성 행동의 dynamics를 다시 확인해 보상을 계산하는 별도 단계는 현재 경로에 없음.
- 형상별 초기 상태를 얻는 `s0_fn`에는 `physical_e(...).detach()`가 전달됨. 따라서 초기 상태 계산을 통한 연속 미분 경로는 끊겨 있지만, E를 네트워크 조건으로 넣는 경로는 있음. 이 동작은 두 모델에 동일함.

## 해석의 한계

[추정] Mode1에서 추가 학습한 차이가 Mode2 공동 생성에 충분히 전달되지 않을 수 있음. 그러나 코드 경로가 다르다는 사실만으로 이번 결과의 원인을 확정할 수 없음. 형상 변화쌍은 형상과 초기 상태가 함께 바뀌고, 추가 모델은 Mode1 감독량과 계산량도 늘어남. 하나의 학습 seed 결과임.

[미검증] Mode1을 이용해 보상을 계산하는 방식이 실제 공동 생성과 10초 task를 개선하는지는 이번 A/B에서 실행하지 않았음. 사전 비교를 유지하기 위해 현재 평가 경로는 바꾸지 않았음. 별도 dynamics 모델로 교체하거나 공동 생성 방향을 변경하지 않았음.
