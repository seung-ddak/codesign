# 추종 잘 된 구간만으로 TT 재학습 (2026-11-10, 사용자 결정 = 원인 확인 2번)

목적: 10k PD 데이터의 낮은 추종 품질 (1 s 회전 상관 0.33, 낙상 64 %) 이 TT 성능 정체의 원인인지 확인.

## 바꾸는 것 (h64_delta_trim 대비 이것만)
| 항목 | h64_delta_trim | 이번 |
|---|---|---|
| 데이터 | 10k PD 전체 (낙상 마지막 1 s 제외) | 에피소드마다 원본 A1 모션을 연속으로 잘 따라간 가장 긴 구간만, 행 앞으로 이동 |
| 추종 기준 (1 s 구간) | 없음 | 회전 변화 오차 < 0.2 rad, 이동 벡터 오차 < 0.1 m (각자의 heading 기준) |

같은 것: 파일·행 순서, train/val 분할, H64, delta, norm-quantile 0.005, 60k step, batch 64, 모델 크기, modes, EMA, seed 0.
예상 남는 양: 약 22 % (파일 8개 시험: 217,547 → 47,446 step), 절반 가까운 에피소드는 2 step 만 남음.

## 평가 (h64_delta_trim 과 같은 에피소드·시드)
1. 재현 확인 (`repro_check.py --n 100`, 원본 데이터 · 넘어지지 않은 100 + 넘어진 100). 실제 행동을 준 예측의 1 s 회전 변화 상관·이동 상관 (사후 계산, 두 모델 동일 방법).
2. 생성 행동 → MuJoCo 10 s 생존 (재현 확인 내 지표).
3. 세 task (원·슬라럼·직진), task_delta_trim_v1 과 같은 명령.

판정 (사전 고정): 1 s 회전 상관이 h64_delta_trim 보다 0.1 이상 오르면 "데이터 품질이 회전 학습을 막았다" 를 지지. 변화 없으면 데이터 품질 외 원인 (모델·학습량·목표) 쪽.
