# H64 재학습 계획: 몸통 변화량(delta) + 넘어짐 구간 제외 + 정규화 범위 조정

상태: 계획 (학습 시작 전, 사용자 승인 대기). 2026-11-10.

## 목적
H64 는 관절각은 맞히지만 몸통 이동을 못 맞힌다 (속도 상관 0.26 / 0.13, "멈춤" 예측보다 나쁨).
원인 후보 2·3 (넘어짐 데이터로 넓어진 정규화 범위, 창 기준 절대 위치 표현) 을 함께 고쳐 몸통 이동 예측이 나아지는지 본다.

## 변경 (H64 대비 이것만 바꾼다)
| 항목 | H64 (기존) | 이번 |
|---|---|---|
| 몸통 위치·yaw 표현 | 창 기준 절대값 (`--pose abs`) | 직전 step 대비 변화량 (`--pose delta`, 기존 옵션) |
| 넘어진 에피소드 | 넘어짐 판정 시점까지 전부 | 넘어짐 직전 1초 (50 step) 제거. 남은 길이 < 64 step 이면 제외 |
| 정규화 범위 | 학습 데이터 최소~최대 | 채널별 0.5%~99.5% 분위 (새 옵션 `--norm-quantile 0.005`, 범위 밖 값은 ±1 밖으로 둔다) |
| 학습량 | 25k step × batch 64 (V100) | 60k step × batch 64 (RTX 4070) |

그대로: 10k 데이터·200 형상, train/val 분할 (source 그룹 기준, 시드 0), H64, d256·6층, FiLM, DDIM 5, modes 0/1/2/4 (.1/.2/.35/.35), EMA .75, lr 2e-4, warmup 500.

확인한 사실: 넘어짐 직전 1초 제거만으로는 회전속도 최댓값이 18.7 → 18.7 rad/s 로 줄지 않는다 (극단값이 드문 튐에서 나옴). 그래서 분위 기반 범위가 필요하다.

## 순서와 예상 시간 (RTX 4070, 측정: 300 step + 검증 3회 + 로딩 = 38 초)
1. 데이터 전처리 — 넘어짐 직전 1초를 valid 마스크에서 제거한 사본 (`data_trim/`, 약 2.6 GB). 10 분
2. 코드 — `train_tt.py` 에 `--norm-quantile` 추가 + 단위 테스트, 300 step 확인 실행. 20 분
3. 학습 — 60k step, 검증 500 step 마다. 첫 1,000 step 속도로 종료 시각 재추정. 약 1.5~2 시간
4. 평가 — 아래 3 가지. 30 분
5. 보고서 — `report/tt_delta_retrain.html`. 20 분
합계 약 3~3.5 시간. 3 단계에서 2.5 시간을 넘길 것으로 보이면 그 시점 checkpoint 로 평가한다.

## 평가 (H64 와 같은 검증 에피소드·시드)
| 지표 | H64 기준값 | 개선 판정 (사전 고정) |
|---|---|---|
| 몸통 수평 속도 상관 (실제 A 제공, 넘어지지 않은 100개) | 0.26 / 0.13 | 둘 다 ≥ 0.5 |
| 몸통 위치 오차 전체 평균 vs "멈춤" 기준 | 57.0 vs 46.6 cm | 기준보다 작음 |
| 1.3 초 이동 방향 코사인 | 0.31 | ≥ 0.6 |
| 발 접촉 정확도 | 57% | ≥ 70% ("항상 4발" 기준) |
| 생성 행동 → MuJoCo 10 초 생존 (넘어지지 않은 100개) | 4 / 100 | ≥ 20 / 100 |

## 이번 범위에서 못 하는 것
- 세 task (원·슬라럼·직진) 평가: reward-gradient·RL 코드가 절대 위치 표현만 지원한다 (`Needs ... absolute pose`). delta 지원은 별도 작업. 이번에는 재현 확인 (위 표) 까지만 한다.
- 원인 2·3 의 기여 분리: 두 변경을 함께 넣으므로 어느 쪽이 효과인지는 가르지 않는다.
