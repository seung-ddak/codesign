# CALM–Co-design 연구: 실험 검증 체크리스트

## 운영 원칙

각 실험은 PASS / FAIL / BLOCKED / NOT RUN 중 하나로 분류한다.

각 단계의 최종 결과에 다음을 반드시 포함한다.

- 실제로 실행한 실험 수와 성공·실패 수
- 통과 조건 및 측정 결과
- 수치와 그래프, 실제 실행 영상
- 확인된 실패 원인과 아직 검증하지 않은 원인 가설
- 사용한 설정, seed, checkpoint, commit SHA
- 다음 단계 진행 가능 여부

**증거 없이 성공 처리하거나, 실패를 숨기기 위해 종료 조건·평가 기준을 수정해서는 안 된다.**

## G0. CALM HLC+LLC 체크포인트 실행 검증

**목표:** 제공된 HLC·LLC 체크포인트가 CALM 원본 A1과 Isaac Gym에서 정상적인 연속 이동을 수행하는지 확인한다.

### 통과 체크리스트

- [ ] HLC와 LLC 체크포인트 모두 정상 로딩
- [ ] 관측값·정규화·latent·관절 출력 차원 일치
- [ ] CALM 원본 제어 설정 유지
- [ ] Default 초기 자세에서 비정상적인 penetration 없음
- [ ] 전진 → 회전 → 횡이동 → 정지 명령 적용
- [ ] 중간 종료·자동 초기화 없이 연속 10초 실행
- [ ] 실제 이동 방향이 명령과 대체로 일치
- [ ] 관절 목표각과 물리 상태에 NaN·Inf 없음
- [ ] 전체 영상·궤적·실행 결과 저장

### 필수 보고 자료

- 실제 A1의 10초 실행 영상
- 명령 속도와 실제 속도 비교 그래프
- XY 이동 궤적
- Yaw 목표와 실제 방향 비교
- 관절각·관절 토크 시계열
- 종료 조건별 진단 결과

### 실패 원인 진단

| 관찰된 현상 | 우선 확인할 원인 |
|---|---|
| 시작 직후 종료 | 종료 플래그, 초기 접촉, 관절 보호 조건 |
| 명령과 반대 방향 이동 | 좌표계, 목표 방향, 관절 순서, 정책 관측값 |
| 제자리에서 떨림 | 초기 penetration, PD 목표각, 관절 제한 |
| 넘어짐 | 물리 설정 불일치, 정책 출력, 접촉 및 토크 |
| HLC는 작동하지만 LLC가 비정상적 | LLC 관측 정규화, latent 처리, 행동 변환 |

**통과 기준:** 연속 10초 수행과 정상적인 명령 반응을 모두 충족해야 한다. 단순히 종료하지 않은 것만으로 통과할 수 없다.

**현재 결과:** 9스텝, 0.30초 종료. FAIL. 정확한 원인은 추가 진단 필요.

## G1. 자동 가상 조이스틱을 통한 다양한 모션 생성

**목표:** 사람이 조이스틱으로 캐릭터를 조작하는 것처럼 다양한 이동 명령을 자동으로 만들어 실제 A1 모션을 수집한다.

### 통과 체크리스트

- [ ] 명령 크기·방향·변화율·지속 시간을 랜덤화
- [ ] 명령 변화가 연속적이며 급격한 불연속 없음
- [ ] HLC 학습 범위 내 명령 생성
- [ ] 직진·후진·횡이동·회전·가감속 생성 확인
- [ ] 서로 다른 연속 방향 전환 생성 확인
- [ ] 각 에피소드 최대 10초
- [ ] 중간 Reset으로 분리된 궤적을 연결하지 않음
- [ ] 동일 seed에서 명령 시퀀스 재현 가능
- [ ] 실패 에피소드도 원본 데이터로 저장

### 필수 보고 자료

- 서로 다른 유형의 실제 모션 영상 모음
- 명령 속도 및 실제 속도의 시간 그래프
- 전체 수집 모션의 XY 궤적 시각화
- 성공·실패 에피소드 수 및 종료 시간 분포
- 명령별 실제 반응 분포

### 실패 원인 진단

| 현상 | 의심 원인 |
|---|---|
| 대부분 직진만 생성 | 명령 생성 범위 부족, HLC 반응 부족 |
| 명령은 다양하지만 실제 동작이 비슷함 | HLC 목표 추종 실패 또는 LLC 표현 범위 부족 |
| 전환할 때 자주 넘어짐 | 명령 변화율 과도, 학습 범위 이탈 |
| 영상은 다양하지만 데이터는 중복 | 초기화 반복, 실제 궤적 중복 |
| 10초 모션이 거의 없음 | 정책 안정성, 명령 강도, 종료 조건 |

**통과 기준:** 다양한 명령뿐 아니라 실제 로봇의 움직임에서도 충분한 차이가 확인되어야 한다.

## G2. 데이터 무결성 및 대표 모션 100개 선정

**목표:** 실제로 수행된 움직임이 서로 다른 Reference Motion 100개를 구축한다.

### 통과 체크리스트

- [ ] Root 위치·방향·속도 저장
- [ ] 12개 관절각·속도 저장
- [ ] 발 위치·접촉 정보 저장
- [ ] 실제 적용한 Action과 HLC 명령 저장
- [ ] 상태 배열과 행동 배열의 시간 대응 검증
- [ ] 성공·실패 및 종료 사유 분리
- [ ] 무효한 물리 계산 데이터 분리
- [ ] 실제 움직임 기준으로 모션 특징 계산
- [ ] 다양성 기반으로 정상 Reference 100개 선정
- [ ] 각 Reference의 전체 10초 연속성 검증
- [ ] 선정된 100개가 서로 중복되지 않음을 확인

### 다양성 평가 지표

이동 속도, 횡방향 속도, 누적 Yaw, Yaw rate, 궤적 곡률, 가속·감속 및 방향 전환 횟수를 사용한다.

### 필수 보고 자료

- 대표 100개 모션의 유형별 분포
- 전체 후보와 선택된 100개의 특징 분포 비교
- 모션 유사도 행렬
- 대표 모션 영상 및 XY 궤적
- 제외된 모션 수와 제외 사유

### 실패 원인 진단

| 현상 | 의심 원인 |
|---|---|
| 유효 모션이 100개 미만 | 수집량 부족, 높은 실패율 |
| 서로 비슷한 모션이 다수 | 데이터 중복, 선정 알고리즘 문제 |
| 특정 이동 유형이 없음 | HLC 명령 탐색 또는 정책 표현 범위 부족 |
| 관절 움직임이 불연속적 | 기록 오류, Reset 연결, 시간축 불일치 |

**통과 기준:** 물리적으로 수행된 서로 다른 10초 Reference 100개 확보. 부족하면 임의로 중복 데이터를 복제하지 않는다.

## G3. TT 고정 형상으로 Retargeting

**목표:** CALM에서 확보한 Reference Motion을 기존 TT topology `00000011`, 고정 형상 `e000`에 맞게 변환한다.

### 통과 체크리스트

- [ ] 원본과 TT 관절 순서·부호 확인
- [ ] Quaternion 순서 및 좌표계 변환 확인
- [ ] 30Hz → 50Hz 시간 변환 검증
- [ ] 10초 전체 길이와 움직임 순서 보존
- [ ] 몸체 위치·방향의 연속성 유지
- [ ] 관절각·관절속도 연속성 유지
- [ ] 발 위치와 접촉 패턴 비교
- [ ] 관절 가동 범위 검증
- [ ] 지면 penetration 여부 검증
- [ ] Retargeting으로 인해 움직임이 달라진 정도 측정

### 필수 보고 자료

- 원본 A1과 Retargeting된 TT 형상 비교 영상
- Root 궤적 겹침 그래프
- 관절각 비교 그래프
- 발 위치·접지 비교
- 최대 관절 한계 초과량 및 지면 관통 깊이
- 모션별 Retargeting 성공·실패표

### 실패 원인 진단

| 현상 | 의심 원인 |
|---|---|
| 다리 움직임 반대 | 관절 순서·부호·무릎 방향 |
| 발이 바닥에 박힘 | IK, 몸체 높이, 발 위치 변환 |
| 움직임이 끊어짐 | 보간 또는 프레임 처리 오류 |
| 방향이 뒤집힘 | 좌표계 및 Quaternion 변환 |
| 몸체 궤적을 따라가지 못함 | 형상 운동학적 한계 |

**통과 기준:** 단순히 변환 파일이 만들어지는 것이 아니라, 물리적으로 수행 가능한 목표 모션인지 확인해야 한다.

## G4. 범용 PPO Motion Tracking 학습

**목표:** 하나의 PPO 정책이 입력된 Reference에 따라 서로 다른 동작을 정확하게 추종하도록 학습한다.

### Curriculum 체크리스트

- [ ] Stage 1: 20개 Reference 학습
- [ ] Stage 1: 모션별 실제 Tracking 평가
- [ ] Stage 1: 통과 기준 확정 및 기록
- [ ] Stage 2: 기존 모션 유지하며 50개로 확대
- [ ] Stage 2: 통과 기준 충족 확인
- [ ] Stage 3: 전체 100개 학습
- [ ] Stage 3: 각 Reference를 시작점부터 10초 평가

단계 전환은 PPO update 수가 아니라 실제 Tracking 성능을 기준으로 한다.

### 필수 평가 지표

- 전체 10초 생존·Tracking 성공률
- Root 위치 오차
- Root Yaw 오차
- Root 선속도·각속도 오차
- 관절각 RMSE
- 발 위치·접촉 오차
- Reference별 통과 여부

### 학습 진행 상태도 별도로 보고

- PPO 전체 학습 Step
- Policy Loss, Value Loss
- Approximate KL
- Entropy
- Clip Fraction
- 평균 Reward 및 Tracking Reward 구성
- 학습 단계별 평가 성능 변화

Loss와 Reward는 학습 진행을 확인하기 위한 지표이며, Tracking 성공의 대체 지표가 아니다.

### 실패 원인 진단

| 현상 | 의심 원인 |
|---|---|
| 서로 다른 Reference에서 비슷한 보행 | Reference 관측 무시, 보상 불균형 |
| 관절은 따라가지만 몸체 궤적이 다름 | Root Tracking 부족, 물리적 불가능성 |
| 자세는 유사하지만 계속 넘어짐 | Retargeting, 접촉, 제어 및 안정성 |
| 특정 모션만 실패 | 학습 불균형, 해당 모션의 운동 가능성 |
| 초기 상태에서 즉시 실패 | RSI penetration, 잘못된 초기 속도 |
| 학습 Reward 증가하지만 실제 오차 개선 없음 | Reward와 성공 기준의 불일치 |
| 기존 모션 성능이 악화 | Curriculum에서 이전 동작 망각 |

### 실패 모션 개선

- [ ] 모션별 실패 원인 분류
- [ ] 학습 가능한 실패 모션의 샘플링 비중 증가
- [ ] 이미 성공한 모션의 성능 유지 확인
- [ ] 물리적으로 불가능한 Reference는 별도 구분
- [ ] 전체 100개에 대한 최종 Tracking 평가

**통과 기준:** 입력 Reference의 실제 궤적과 움직임을 정확하게 재현해야 한다. 안정적인 보행만으로는 통과할 수 없다.

정량 기준은 Stage 1의 초기 결과 및 물리적 허용 오차를 함께 검토해 확정하고, 후속 실험에서 임의로 변경하지 않는다.

## G5. 다양한 Morphology E로 확대

**목표:** 범용 Tracking 정책이 A1과 동일한 topology를 유지하면서 다양한 연속 형상 파라미터 E에 대응하도록 확대한다.

### 통과 체크리스트

- [ ] 형상 파라미터 E가 실제 로봇 모델에 반영됨
- [ ] 다리 길이·질량·관성·충돌 형상의 일관성 검증
- [ ] 각 형상의 Reference를 올바르게 Retargeting
- [ ] PPO가 현재 형상 E에 대한 정보를 받음
- [ ] 여러 형상에서 같은 Reference Tracking 평가
- [ ] 형상별 성공률과 Tracking 오차 계산
- [ ] 일부 형상만 학습에 성공하는 편향 확인
- [ ] 미학습 형상에서의 추종 평가를 별도 기록

### 필수 보고 자료

- 형상 E별 실제 로봇 이미지
- 형상별 Tracking 성공률
- 형상별 Root 및 관절 Tracking 오차
- 동일 Reference를 서로 다른 E에서 실행한 비교 영상

### 실패 원인 진단

| 현상 | 의심 원인 |
|---|---|
| 한 형상에서만 성공 | 형상 조건화 부족, 학습 범위 부족 |
| 형상 변경 시 관절 한계 위반 | Retargeting 또는 형상 설계 문제 |
| 형상을 바꿨는데 실제 물리가 같음 | E가 MJX 모델에 제대로 반영되지 않음 |
| 형상별 성능 차이가 극단적 | 물리적 가능 범위 및 학습 데이터 불균형 |

**통과 기준:** 여러 실제 형상에서 Tracking이 수행되며, 형상별 성공·실패 원인이 파악되어야 한다.

## G6. MJX Dynamics Rollout 데이터셋 구축

**목표:** 다양한 E에서 실제 물리 상태와 행동의 관계를 수집한다.

### 통과 체크리스트

- [ ] 실제 MJX 상태 S 저장
- [ ] 실제 적용된 관절 목표각 A 저장
- [ ] 해당 행동에 따른 다음 상태 S' 저장
- [ ] Morphology E가 각 Episode에 정확히 연결됨
- [ ] Action과 다음 상태의 시간 순서 검증
- [ ] Reset 전후 가짜 상태 전이 없음
- [ ] 정상 상태 전이와 실패 상태 전이 보관
- [ ] NaN·무효 물리 상태 제거
- [ ] 실패 구간의 라벨 정의 명확화
- [ ] TT 학습 샘플링 정상:실패 = 80:20 구현
- [ ] E, S, A의 분포 및 다양성 분석

### 필수 보고 자료

- 총 Episode 수와 상태 전이 수
- 형상 E별 데이터 분포
- 정상·실패 전이 수 및 비율
- 상태·행동 분포 그래프
- 무효 데이터 비율
- 저장 데이터의 MJX 재실행 일치 검증 결과

### 실패 원인 진단

| 현상 | 의심 원인 |
|---|---|
| 같은 A에서 S'가 저장된 값과 다름 | 행동 변환·기록 시점 불일치 |
| 실패 데이터가 거의 없음 | 수집 정책의 상태·행동 범위 부족 |
| 특정 E 데이터만 많음 | 형상 샘플링 불균형 |
| 갑작스러운 비물리 상태 변화 | Reset 연결, 저장 오류 |
| 형상에 따른 물리적 차이가 보이지 않음 | E 적용 또는 데이터 구성 오류 |

**통과 기준:** 저장된 데이터가 실제 MJX에서 발생한 물리적 상태 전이를 정확하게 나타내야 한다.

---

## G7. TT Dynamics 학습 및 검증

**목표:** TT가 형상 E, 상태 S, 행동 A 사이의 물리적 관계를 제대로 학습했는지 확인한다.

### 통과 체크리스트

- [ ] Reward를 사용하지 않고 TT 사전학습
- [ ] 학습·검증 데이터를 Episode 단위로 분리
- [ ] 초기 상태 s0 분포 확인
- [ ] 물리적으로 유효한 s0에서 생성 가능
- [ ] One-step 예측 오차 평가
- [ ] Multi-step 예측 오차 평가
- [ ] 2초 예측과 실제 MJX 비교
- [ ] 4초 예측과 실제 MJX 비교
- [ ] 10초 예측과 실제 MJX 비교
- [ ] E 변화에 따른 다음 상태 변화 예측 검증
- [ ] A 변화에 따른 다음 상태 변화 예측 검증
- [ ] 다양한 E에서 예측 오차가 균형적으로 유지되는지 확인

### 필수 보고 자료

- Training/Validation Loss
- 예측 Horizon별 상태 오차
- Predicted vs Actual 이동 궤적
- 실제 MJX와 TT 예측 비교 영상
- E 변경 실험의 예측·실제 반응 비교
- A 변경 실험의 예측·실제 반응 비교
- 초기 상태 관통·전복 비율

### 실패 원인 진단

| 현상 | 의심 원인 |
|---|---|
| Loss는 낮지만 실제 예측이 부정확 | 학습 분포 부족, 학습·평가 불일치 |
| 짧게는 맞지만 길어지면 틀림 | 누적 Dynamics 오차 |
| E를 바꿔도 예측이 동일 | E 조건화 부족, 형상 데이터 다양성 부족 |
| A를 바꿔도 예측이 동일 | Action 민감도 부족 |
| 생성 직후 넘어짐 | s0 유효성 및 초기화 분포 불일치 |
| 학습에서 보지 못한 형상에서만 실패 | 형상 일반화 한계 |

**통과 기준:** Loss뿐 아니라 실제 MJX 물리 결과와의 예측 일치도, 형상 및 행동에 대한 민감도가 확인되어야 한다.

특히 기존 V7에서 나타난 E 무시 문제와 장기 예측 오차 누적이 다시 발생하지 않았는지 확인해야 한다.

## G8. 새로운 복합 Task에서 E·A 공동 생성

**목표:** TT가 학습 중 보지 못한 복합 과제의 Reward만으로 최적 형상과 행동 궤적을 생성하는지 검증한다.

### 통과 체크리스트

- [ ] 새로운 복합 Task Reward 정의
- [ ] TT 학습에는 해당 Task Reward를 사용하지 않음
- [ ] 추론 단계에서 E와 A 공동 생성
- [ ] 생성된 s0의 물리적 유효성 확인
- [ ] 10초 Action 전체를 Open-loop로 실행
- [ ] 실제 MJX에서 Task 수행 검증
- [ ] 넘어진 시점과 충돌 기록
- [ ] 실제 Task 성공률 계산
- [ ] Predicted Reward와 MJX Actual Reward 비교
- [ ] 고정 E 실험과 공동 생성 E 실험 비교
- [ ] 형상 선택에 따른 실제 물리적 성능 차이 확인

### 필수 보고 자료

- 생성된 로봇 형상 이미지
- 생성된 10초 행동 궤적
- 실제 MJX 수행 영상
- Task 성공·실패 사례
- 실제 충돌 횟수·완주율·진행 거리
- Predicted vs Actual Reward
- 고정 형상 대비 공동 생성 성능 비교

### 실패 원인 진단

| 현상 | 의심 원인 |
|---|---|
| 예측에서는 성공하지만 MJX에서는 실패 | Dynamics 예측 오차, Reward 악용 |
| 로봇은 생존하지만 Task 미완수 | Guidance 부족, 행동 생성 실패 |
| E가 변하지 않음 | E 생성·Guidance 조건 문제 |
| E는 변하지만 실제 성능 개선 없음 | 형상별 Dynamics 예측 또는 형상 선택 문제 |
| 처음부터 넘어짐 | s0 및 접촉·형상 유효성 문제 |
| 짧은 Task는 성공하지만 10초 실패 | 장기 Open-loop Dynamics 오차 |

**통과 기준:** 실제 MJX에서 새로운 Task를 수행해야 한다. 단순한 10초 생존이나 높은 Predicted Reward는 성공이 아니다.
