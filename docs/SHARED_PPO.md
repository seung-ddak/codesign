# 다중 형상 공유 PPO

**형상·모션마다 별도 정책을 만들지 않고 하나의 PPO를 학습한다.**

- 에피소드 시작: 현재 난이도에서 형상을 균등 선택 → 모션 선택 → RSI 시작 시점 선택.
- 종료 전까지 형상을 유지한다. 형상별 물리 모델·목표·관측 E를 함께 변경한다.
- 기본 난이도는 환경별 누적 제어 step 0/3,000/9,000에서 확대한다. 자동 성능 판정 방식은 아니다.
- 학습·검증 형상과 모션은 겹치면 실행을 중단한다. 모델/Reference의 E 불일치, 비정상 값, 관절 한계 위반도 거부한다. 이 검사는 동적 추종 가능성을 판정하지 않는다.

## 실행

현재 준비된 30Hz 자료로 e000·다리 비율 변형 2개를 학습하고, e003·e008 및 제외한 모션 007에서 검증한다. 100개 연속동작과 128개 형상은 아직 준비하지 않았다.

```bash
cd /home/cgr-ugrad-2026/quad_ws/codesign
WANDB_MODE=offline MUJOCO_GL=egl XLA_PYTHON_CLIENT_PREALLOCATE=false ../transformer-transformer/.venv/bin/python \
  code/motion_tracking/train_rl_procedural.py --config-name run_shared_ppo
```

성공·실패의 실제 물리 궤적도 저장하려면 다음 인자를 덧붙인다. 종료 전 상태를 저장하므로 초기화된 상태가 다음 상태로 섞이지 않는다.

```bash
rollout_dir=/home/cgr-ugrad-2026/quad_ws/codesign/runs/calm_shared_ppo/try1/rollouts
```

`failed/`, `completed/`에 E, 실제 상태·다음 상태, 정책 출력 action, 실제 적용 관절 목표 ctrl, 모션 번호·종료 프레임·제어 간격을 저장한다. 모션 끝 도달은 정상 종료다. 실제 적용 행동은 `ctrl`이며 정규화된 정책 출력과 구분한다. 기록은 메모리의 에피소드 버퍼를 종료 시 디스크에 옮긴다. 저장을 켜면 디스크 사용량과 입출력이 증가한다. 기본값은 기록 끔이다.

## 결과 판정

- [ ] 학습 형상에서 10초 생존과 추종 오차가 개선되는가?
- [ ] 미학습 형상·모션에서도 개선되는가? 학습 Reward와 따로 판정한다.
- [ ] 난이도 확대 직후 성능이 무너지면 해당 형상들의 목표·초기 상태·접지와 정책 성능을 먼저 비교한다.
- [ ] 생존만으로 정확한 추종이나 TT 데이터의 충분성을 선언하지 않는다.

32개 병렬 환경으로 시작한다. 형상 수를 늘릴 때 모델·Reference 뱅크 메모리도 함께 증가하므로 병렬 수만으로 메모리 상한이 보장되지는 않는다. 기존 e000 체크포인트는 E 관측이 없으므로 그대로 이어 학습하지 않는다. 새 학습은 별도 체크포인트를 만든다.

기존 파이프라인의 ‘모션별 expert’를 ‘Reference 조건부 공유 expert’로 변경하는 구현이다. PPO가 수집 수단이고 TT가 Reward-agnostic Dynamics를 학습한다는 목표는 유지한다.

## 구현 검증 결과

자동 테스트 7개 통과. GPU에서 형상 재선택·관측 E·실제 상태 연속성·8개 종료 궤적 저장을 확인했다. 별도로 128스텝 PPO 업데이트, 미학습 형상/모션 평가, 0/128 체크포인트 저장까지 통과했다. 이는 기능 검증이며 수렴·10초 추종 성능을 검증한 학습 결과가 아니다. 기록은 `runs/calm_shared_ppo/try1/verification.json`과 `integration.log`에 있다.
