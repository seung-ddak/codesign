이전 `calm_composed_10000` 폴더는 사용자 요청에 따라 삭제했다. 이전 데이터를 새 수집에 재사용하지 않는다.

## 길이와 구간

K=1~5는 10초(300 전이·301 상태), K=6~12는 20초(600 전이·601 상태), 제어 주기는30Hz다. 동작 인덱스는 0전진·1후진·2좌이동·3우이동·4CW·5CCW·6좌회전 후 직진·7우회전 후 직진·8좌회전 후 후진·9우회전 후 후진·10앉기·11일어나기다.

K별 833~834개를 목표로 한다. 동작 시간 비중은 부족한 동작을 우선하는 기존 계획기를 유지하지만 실제 수행·정지 제외 검사로 계획과 실제 비중이 달라질 수 있다. 최종 비중은 보고서에서 확인한다. 서로 다른 길이는 동일 batch에서 섞지 않는다. 복합 모션의 앉기는1.6~1.8초, 일어나기는1.5~1.7초로 제한하고 남는 시간을 이동·회전에 배분해 자세 전환 뒤 긴 정지를 만들지 않는다.

## 유효 모션

실제 물리 궤적의 각 구간에서 1초 전과 비교해 다음 중 하나 이상을 충족한 시점을 활동으로 판단한다. 구간이1초보다 짧으면 구간 전체의 변화를 사용한다.

- 월드 XY 위치 변화 ≥3cm
- 바라보는 yaw 변화 ≥5도
- 몸통 높이 변화 ≥2cm

각 구간에서 비교 시점의50% 이상이 활동 상태여야 하며, 연속 비활동은1.5초 이하여야 한다. 앉기·일어나기에도 적용한다. 시작·끝의 위치 차이만으로 통과시키지 않는다. 작은 수치 흔들림이나 잠깐 움직인 후 오래 정지하는 궤적을 제외한다.

기존의 동작별 방향·회전·높이 수행 검사와 낙상·비유한 값·완전한 상태 수 검사도 함께 적용한다. 검사 수치와 활동 비율·최장 정지 시간은 시도별 journal에 기록한다. 근접 중복 거리는0.03, 특징은32개 시간 지점의 정규화된 위치·yaw·관절각이다. 이 기준이 모든 의미적 중복이나 미끄러짐을 검증하는 것은 아니다.

## 실행과 재개

본 수집은 `calm-motion-10000.service` 사용자 systemd 서비스로 실행한다. 대화가 종료되어도 계속 실행하며 오류 종료 시15초 뒤 재개한다. 파일 lock으로 중복 실행을 막고, 이미 통과한 ID를 복원한다. 소스·정책·계획 해시가 바뀌면 재개를 거부한다.

최대100,000시도 안에서 통과10,000개를 목표로 한다. 미달 시 `incomplete`로 구분한다. 실패한 slot은 같은 K에서 다른 조합·속도로 재시도한다.

```bash
# codesign 디렉터리에서, 기존 서비스가 실행 중이지 않을 때만 실행
OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 MPLCONFIGDIR=/tmp/calm-motion-mpl \
LD_LIBRARY_PATH=/home/cgr-ugrad-2026/miniconda3/envs/rlgpu/lib \
/home/cgr-ugrad-2026/miniconda3/envs/rlgpu/bin/python -u \
code/motion_tracking/collect_calm_sequences.py \
--out 'runs/calm_motion_10,000/dataset' --batch 16 --max-attempts 100000
```

정적 지표는 동작별 시간 비중·K 분포·시간 구성 지도다. 지도는0~20초를 표시하며10초 모션의 종료 뒤는 흰색, 미수집은 회색이다. 실제 전체 라벨은 timeline_labels.npz에 -2(길이 밖)·-1(미수집)·0~11(동작)로 저장한다.

## 검증

CPU 전체 테스트152개 통과. 짧게 움직인 뒤 정지하는 경우·작은 흔들림·높이 변화가 지나치게 작은 경우를 탈락시키고,20초 제자리 회전과 실제 높이 변화는 통과시키는 테스트를 포함한다. GPU 소규모 실행에서10초·20초 전이/상태 길이와 실제 시간 변화 검사·탈락 기록을 확인했다. 시험 출력은 /tmp에 두었다.

최종 GPU 소규모 검증: K=1~12 각각2개씩, 총24개를30시도에서 확보했다(실패6, 근접 중복0).10초·20초 파일의 상태/전이 수와 시도별 시간 변화 기준을 재검증했다.
