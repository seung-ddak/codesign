# v13: 실제 손실 기여율 20/20/20/20/10/10

사용자의 정정에 맞춰 고정 계수 방식에서 실제 합산 손실 비율을 맞추는 방식으로 수정했다. 전체60000step 학습과 기본 예측 진단을 완료했다. 약9.35분 소요됐다.

1. 실제 합산 손실에서 행동·관절각·관절속도·몸통은 각각20%, 발 접지·형상E 생성은 각각10%가 되도록 매 학습 묶음에서 계수를 자동 조절한다. 오차가 큰 항목은 계수를 낮추고 작은 항목은 높인다. 항목 안에서는 예측해야 하는 유효한 값의 평균 오차를 계산한다.
2. 몸통14개는 XY위치2·높이1·yaw의 cos/sin2·중력방향3·선속도3·각속도3이다. 관절각·관절속도·행동은 각각12개, 접지4개, E13개다. 데이터·구조·정규화·Mode1/2/4 표본 비율20/40/40·학습 횟수는 v12와 같다.
3. 조절 계수 계산은 역전파에서 상수로 취급해 각 항목의 학습 신호가 사라지지 않게 한다. 다만 보장하는 비율은 합산 손실의 숫자 비율이다. 모델 파라미터 업데이트에 각 항목이 미치는 비율까지 고정한다는 뜻은 아니다.
4. 이미 조건으로 주어진 행동·E는 예측 대상이 아니므로 그 구간의 생성 손실은0이다. 그런 항목을 제외한 비율은 원래 비율 관계를 유지한다. 모든 여섯 항목이 예측 대상이고 오차가 양수인 일반 학습 묶음에서는 실제 비율이20/20/20/20/10/10이다. 오차가 정확히0이면 기여0이며, 매우 작은 오차의 과도한 확대를 막으려고 역수 분모에1e-12 하한을 둔다. 하한보다 작은 오차에서는 비율의 정확한 고정이 보장되지 않는다.
5. 실제 비율을 강제로 맞추면 loss/val_loss 합은 거의 일정해진다. 이 숫자로 수렴·성능을 판단하지 않는다. 학습 개선은 조정 전 오차 raw_loss/val_raw_loss 및 항목별 raw_group_mse/val_raw_group_mse로 확인한다. 실제 손실 비율은 loss_group_fractions/val_loss_group_fractions에 기록한다.

구현 검증은 관련 자동 검증17개와 실제 작은 모델 GPU1step이다. 서로 크게 다른 오차에서도 요청한 실제 기여율을 맞추고 모든 항목에 학습 신호가 남는지 확인했다. GPU 로그의 실제 비율과 원래 오차는 verification.json에 저장했다. 이 결과는 성능 개선을 입증하는 전체 학습 결과가 아니다. 이전 고정 계수 검증은 coefficient_only_verification.json에 구분해 남겼다.

저장소 루트의 GPU가 보이는 일반 터미널에서 실행한다.

```bash
../transformer-transformer/.venv/bin/python -u runs/pipeline_v1/fast_mode24_v13_group_loss/run_train.py
```

이 명령은 학습과 train_tt.py의 기본 학습 후 진단을 실행한다. 전체 생성/MJX 비교는 포함하지 않는다. CPU2스레드·Torch GPU 메모리60% 제한, /home 임시 파일·캐시, 입력·구현 해시 확인, 기존 checkpoint 덮어쓰기 방지를 적용한다.

실제 기여율 조절은 `--loss-group-weights .2 .2 .2 .2 .1 .1 --loss-balance actual`로 활성화한다. 새 v13 설정에는 두 옵션이 모두 지정되어 있다. `--loss-balance coefficients`는 이전 고정 계수 방식이고, 그룹 가중치를 생략하면 과거 원래 손실이다.
